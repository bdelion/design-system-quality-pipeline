# Règles métier

## Règles explicitement présentes dans les spécifications

- Une issue Done doit être associée à au moins une PR pour les cas concernés.
- Un bug ordinaire et un bug d'audit sont distincts pour le suivi RGAA/WAI-ARIA.
- Les criticités d'accessibilité ne doivent pas être confondues avec les autres domaines de criticité.
- Une issue Cancelled ne doit pas avoir de référence PR.
- Une issue Grooming ne doit pas avoir d'Iteration, de Velocity ni de Milestone.
- Une issue Backlog doit notamment conserver Grooming et ne pas être engagée.

**Attention :** certaines règles sont exprimées avec des exceptions dans le workflow par type d'issue. Elles ne doivent donc pas être codées comme des invariants universels sans matrice de profil.
